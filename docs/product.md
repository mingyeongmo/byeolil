# 별일있음 Product Document

## 1. 프로젝트 소개

### 서비스명

별일있음

### 한 줄 소개

평범한 하루를 쓸데없이 거창하고 웃기게 만들어주는 AI 과장 생성 웹서비스

### 프로젝트 목적

사용자가 오늘 있었던 평범한 일들을 짧게 입력하면, AI가 이를 전설, 긴급 뉴스, 스포츠 중계, 업적 달성 등 과장된 스타일의 콘텐츠로 변환한다.

사용자는 별일 없었던 하루도 재미있는 콘텐츠로 만들고, 완성된 결과를 이미지나 링크로 다른 사람에게 공유할 수 있다.

---

## 2. 해결하고 싶은 문제

대부분의 사람에게는 특별한 사건 없이 지나가는 평범한 날이 많다.

기존 일기 서비스는 사용자가 직접 긴 글을 작성해야 하기 때문에 기록에 부담을 느낄 수 있다. 또한 범용 AI를 사용하면 사용자가 직접 프롬프트를 작성하고 결과 형식을 정해야 한다.

별일있음은 다음과 같은 경험을 제공한다.

- 사용자는 오늘 있었던 일을 짧게만 입력한다.
- 원하는 과장 스타일을 선택한다.
- AI가 즉시 재미있는 콘텐츠로 변환한다.
- 공유하기 좋은 결과 카드로 제공한다.

---

## 3. 주요 사용자

### 핵심 사용자

- 재미있는 웹 콘텐츠를 가볍게 즐기고 싶은 사람
- 평범한 일상을 친구와 재미있게 공유하고 싶은 사람
- 긴 일기를 작성하는 것은 부담스럽지만 하루를 기록하고 싶은 사람
- AI 프롬프트를 직접 작성하지 않고 결과를 얻고 싶은 사람

### 사용 환경

- 모바일 웹 중심
- 카카오톡이나 SNS 링크를 통한 접속
- 회원가입 없이 바로 사용
- 짧은 시간 안에 결과 생성

---

## 4. 핵심 사용자 가치

사용자는 별일 없었던 하루를 입력하는 것만으로 재미있고 공유하고 싶은 콘텐츠를 얻을 수 있다.

서비스의 핵심 가치는 AI 기술 자체가 아니라 다음의 간단한 사용자 경험이다.

> 오늘 한 일 입력 → 과장 스타일 선택 → 결과 생성 → 저장 또는 공유

---

## 5. 핵심 사용자 흐름

1. 사용자가 서비스에 접속한다.
2. 오늘 있었던 일을 3~5개 이상 입력한다.
3. 원하는 과장 스타일을 선택한다.
4. 생성 버튼을 누른다.
5. AI가 과장된 결과를 생성한다.
6. 사용자가 결과 카드를 확인한다.
7. 결과를 이미지로 저장하거나 내용을 복사한다.
8. 같은 내용으로 다른 스타일의 결과를 다시 생성할 수 있다.

---

## 6. MVP 기능

### 6.1 이름과 오늘 한 일 입력

- 이름 입력
- 최소 3개, 최대 5개 입력
- 입력 항목 추가 및 삭제
- 빈 값 제출 방지
- 항목별 최대 글자 수 제한
- 현재 입력 개수 표시

### 6.2 과장 스타일 선택

첫 번째 버전에서는 다음 네 가지 스타일을 제공한다.

- 전설
- 긴급 뉴스
- 스포츠 중계
- 업적 달성

사용자는 한 번에 하나의 스타일을 선택할 수 있다.

### 6.3 AI 결과 생성

사용자가 입력한 활동과 선택한 스타일을 서버에 전달한다.

AI는 다음 내용을 생성한다.

- 제목
- 본문
- 오늘의 칭호
- 한 줄 총평

### 6.4 결과 화면

결과 화면에는 다음 내용을 표시한다.

- 선택한 과장 스타일
- 생성된 제목
- 생성된 본문
- 오늘의 칭호
- 한 줄 총평

### 6.5 결과 활용

- 결과 내용 복사
- 결과 이미지 저장
- 같은 내용으로 다른 스타일 선택
- 처음부터 다시 작성

---

## 7. MVP에서 제외할 기능

첫 번째 버전에서는 다음 기능을 구현하지 않는다.

- 회원가입 및 로그인
- 사용자 프로필
- 데이터베이스 영구 저장
- 다른 사용자의 결과를 보는 공개 피드
- 좋아요와 댓글
- 친구 초대
- 결과 링크 공유
- 결제 및 구독
- 사용자 작성 스타일
- 모바일 애플리케이션

결과 링크 공유는 MVP 출시 후 사용자의 공유 수요를 확인한 뒤 추가한다.

## 8. 결과 예시

### 사용자 입력

- 민경모
- 늦잠을 잤다.
- 점심을 먹었다.
- 게임을 했다.
- 낮잠을 잤다.

### 선택한 스타일

긴급 뉴스

### 생성 결과

#### 제목

[속보] 오전 일정 전면 붕괴…정오부터 공식 활동 시작

#### 본문

관계자에 따르면 민경모는(은) 늦잠으로 오전 일정을 전면 중단한 뒤, 점심 식사를 통해 가까스로 활동을 시작했다. 이후 게임 산업에 모든 역량을 집중했지만, 오후 들어 급격한 체력 저하를 이유로 다시 수면에 돌입한 것으로 확인됐다.

#### 오늘의 칭호

두 번 잠든 자

#### 한 줄 총평

생산성은 발견되지 않았으나 체력 보존에는 성공했다.

## 9. 제품 원칙

### 간단해야 한다

사용자는 별도의 설명 없이도 입력과 생성을 완료할 수 있어야 한다.

### 빨라야 한다

서비스 접속부터 결과 확인까지 오래 걸리지 않아야 한다.

### 결과가 재미있어야 한다

AI가 단순히 문장을 길게 바꾸는 것이 아니라, 사용자가 웃고 다른 사람에게 보여주고 싶은 결과를 만들어야 한다.

### 모바일에서 편해야 한다

작은 화면에서도 입력, 스타일 선택, 결과 확인이 편리해야 한다.

### 사용자가 통제할 수 있어야 한다

사용자는 원하는 과장 스타일을 직접 선택하고, 결과가 마음에 들지 않으면 다시 생성할 수 있어야 한다.

## 11. 성공 여부를 확인할 지표

MVP 배포 후 다음 행동을 측정한다.

- 서비스를 방문한 사용자 중 생성을 시작한 비율
- 생성 요청을 완료한 비율
- 결과 복사 또는 이미지 저장 비율
- 다른 스타일로 다시 생성한 비율
- 사용자가 가장 많이 선택한 과장 스타일
- 생성 과정에서 이탈한 화면

---

## 12. 예상되는 문제

### AI 결과가 재미없을 수 있다

스타일별 프롬프트와 결과 예시를 지속적으로 개선한다.

### 결과 생성 시간이 길 수 있다

생성 중이라는 사실을 알 수 있는 로딩 화면과 메시지를 제공한다.

### API가 실패할 수 있다

사용자에게 이해하기 쉬운 오류 메시지와 다시 시도하기 버튼을 제공한다.

### API 비용이 증가할 수 있다

입력 글자 수와 생성 횟수를 제한하고, 지나치게 긴 결과 생성을 방지한다.

### 부적절한 입력이 들어올 수 있다

입력 길이 제한과 필요한 안전 처리를 적용한다.
