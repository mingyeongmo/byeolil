# 별일있음 Product Document

## 1. 프로젝트 개요

### 서비스명

별일있음

### 한 줄 소개

평범한 하루를 쓸데없이 거창하고 웃기게 만들어주는 AI 과장 생성 웹서비스

### 현재 상태

- 모바일 중심 웹 MVP 구현 및 Vercel 배포
- OpenAI를 이용한 결과 생성
- Neon DB를 이용한 UUID 결과 링크 제공
- 카카오톡, X, 링크 복사 및 결과 이미지 저장 지원
- 생성 후 7일이 지난 결과의 일 1회 자동 삭제

### 프로젝트 목적

사용자가 오늘 있었던 평범한 일을 짧게 입력하면 AI가 전설, 긴급 뉴스,
스포츠 중계, 업적 달성 중 선택한 스타일의 콘텐츠로 변환한다.

사용자는 별일 없었던 하루도 재미있는 콘텐츠로 만들고 완성된 결과를
이미지나 링크로 다른 사람에게 공유할 수 있다.

---

## 2. 해결하고 싶은 문제

특별한 사건 없이 지나가는 평범한 날은 기록할 이야기가 없다고 느끼기 쉽다.
기존 일기 서비스는 사용자가 직접 긴 글을 작성해야 하고, 범용 AI 서비스는
프롬프트와 결과 형식을 직접 정해야 한다.

별일있음은 다음과 같은 간단한 경험을 제공한다.

- 오늘 있었던 일을 짧은 문장으로 입력한다.
- 원하는 과장 스타일 하나를 선택한다.
- AI가 정해진 형식의 재미있는 결과를 생성한다.
- 공유하기 좋은 결과 카드로 저장하거나 링크를 보낸다.

---

## 3. 주요 사용자와 사용 환경

### 핵심 사용자

- 재미있는 웹 콘텐츠를 가볍게 즐기고 싶은 사람
- 평범한 일상을 친구에게 재미있게 공유하고 싶은 사람
- 긴 일기 작성은 부담스럽지만 하루를 기록하고 싶은 사람
- AI 프롬프트를 직접 작성하지 않고 결과를 얻고 싶은 사람

### 사용 환경

- 모바일 웹 중심
- 카카오톡이나 SNS 링크를 통한 접속
- 회원가입 없이 바로 이용
- 약 1분 안에 입력부터 결과 확인까지 완료

---

## 4. 핵심 사용자 가치

서비스의 핵심 가치는 AI 기술 자체보다 다음의 단순한 사용자 경험에 있다.

> 오늘 한 일 입력 → 과장 스타일 선택 → 결과 생성 → 저장 또는 공유

사용자는 평범한 하루를 입력하는 것만으로 웃고 다른 사람에게 보여주고 싶은
콘텐츠를 얻을 수 있어야 한다.

---

## 5. 현재 사용자 흐름

1. 사용자가 랜딩 페이지에서 서비스 설명을 확인한다.
2. \`내 하루 과장하러 가기\`를 눌러 입력 페이지로 이동한다.
3. 이름 또는 별명과 오늘 있었던 일을 3개 이상 입력한다.
4. 네 가지 과장 스타일 중 하나를 선택한다.
5. \`내 하루 과장하기\`를 누른다.
6. 서버가 입력값을 검증하고 OpenAI에 결과 생성을 요청한다.
7. 생성 결과를 Neon DB에 저장하고 UUID 결과 주소를 만든다.
8. 사용자가 결과 카드와 스타일별 화면을 확인한다.
9. 결과를 이미지로 저장하거나 카카오톡, X, 링크 복사로 공유한다.
10. 새로운 하루를 다시 작성하거나 처음 화면으로 돌아간다.

## 6. 구현된 MVP 기능

### 6.1 랜딩 페이지

- 간단한 서비스 설명과 대표 이미지
- 약 1분이라는 예상 이용 시간 표시
- 로그인 없이 시작할 수 있다는 안내
- 카카오톡, X, 링크 복사를 통한 서비스 공유

### 6.2 이름과 오늘 한 일 입력

- 이름 또는 별명 입력
- 이름 최대 20자 제한
- 오늘 있었던 일 최소 3개 입력
- 입력 항목 개수의 최대 제한 없음
- 항목 추가 및 최소 3개를 제외한 항목 삭제
- 활동별 최대 50자 제한
- 빈 값과 의미 없는 입력 방지
- 잘못된 항목 아래에 오류 메시지 표시

### 6.3 과장 스타일 선택

다음 네 가지 스타일 중 하나를 선택한다.

- 전설
- 긴급 뉴스
- 스포츠 중계
- 업적 달성

스타일을 선택하기 전에는 생성 버튼을 사용할 수 없으며, 이전 단계로 돌아가
입력 내용을 수정할 수 있다.

### 6.4 결과 생성과 검증

- \`POST /api/generate\` Route Handler 사용
- Zod를 이용한 클라이언트 요청값 재검증
- OpenAI Responses API를 서버에서만 호출
- Mock 결과와 실제 OpenAI 결과 모드 지원
- 구조화된 결과를 Zod 스키마로 검증
- 지원하지 않는 문자가 섞인 결과 차단
- 제목, 본문, 오늘의 칭호, 한 줄 총평 생성
- 생성 중 중복 요청 방지와 오류 메시지 표시

### 6.5 결과 저장과 동적 페이지

- Neon DB에 이름 또는 별명, 선택 스타일과 생성 결과 저장
- 사용자가 입력한 오늘 있었던 일은 Neon DB에 저장하지 않음
- UUID 기반 \`/result/[id]\` 결과 주소 생성
- 주소를 아는 사용자가 결과를 볼 수 있는 공개형 링크
- 생성 결과를 7일 동안 보관하고, 보관 기간이 지난 결과를 일 1회 자동 삭제
- 존재하지 않거나 삭제된 결과를 위한 별일있음 전용 404 화면

### 6.6 스타일별 결과 화면

결과 카드의 큰 구조는 유지하면서 선택한 스타일에 따라 색상과 장식을 다르게
표시한다.

- 전설: 아이보리와 골드
- 긴급 뉴스: 레드와 네이비
- 스포츠 중계: 네이비와 그린
- 업적 달성: 퍼플

### 6.7 결과 활용과 공유

- \`html-to-image\`를 이용한 결과 카드 PNG 저장
- 카카오 JavaScript SDK의 \`Kakao.Share.sendScrap()\`을 이용한 카카오톡 공유
- X Intent를 이용한 게시물 작성
- 현재 페이지 주소 복사와 중앙 토스트
- 랜딩 페이지와 결과 페이지의 공유 문구 및 주소 분리
- 결과별 제목과 설명을 포함한 Open Graph 및 X 메타데이터
- 랜딩 페이지와 결과 페이지에 공통 정적 공유 이미지 사용

### 6.8 정책과 운영 보호

- 이용약관과 개인정보처리방침 제공
- 이메일을 통한 결과 삭제 및 개인정보 관련 요청 접수
- Vercel Firewall에서 \`/api/generate\`를 같은 IP 기준 10분에 10회로 제한
- 제한 초과 시 \`429\` 상태에 맞는 사용자 안내 표시
- Vercel Cron으로 오래된 결과 삭제 API를 일 1회 호출
- \`CRON_SECRET\`으로 삭제 API의 비인가 요청 차단

## 7. 현재 데이터 흐름

1. \`ActivityForm\`이 이름과 활동을 입력받고 클라이언트에서 1차 검증한다.
2. \`CreatePage\`가 입력값과 선택한 스타일을 상태로 관리한다.
3. \`CreatePage\`가 \`/api/generate\`로 JSON 요청을 보낸다.
4. API Route가 \`GenerateRequestSchema\`로 요청을 다시 검증한다.
5. Mock 모드에서는 스타일별 Mock 결과를 사용한다.
6. 실제 모드에서는 OpenAI Responses API로 구조화된 결과를 생성한다.
7. 서버가 결과 형식과 문자를 검사한다.
8. 이름, 스타일과 생성 결과를 Neon DB에 저장한다.
9. 서버가 생성된 UUID를 클라이언트에 반환한다.
10. 클라이언트가 \`/result/[id]\`로 이동한다.
11. 결과 페이지가 UUID로 DB를 조회해 결과를 표시한다.
12. Vercel Cron이 일 1회 \`/api/cron/delete-expired-results\`를 호출한다.
13. 삭제 API가 요청을 인증하고 생성 후 7일이 지난 결과를 삭제한다.

## 8. 데이터 처리 기준

### OpenAI로 전달하는 정보

- 이름 또는 별명
- 오늘 있었던 일
- 선택한 과장 스타일

위 정보는 과장 결과 생성에 사용된다.

### Neon DB에 저장하는 정보

- 이름 또는 별명
- 선택한 과장 스타일
- 생성된 제목
- 생성된 본문
- 오늘의 칭호
- 한 줄 총평

오늘 있었던 일의 원문은 Neon DB에 저장하지 않는다. 자세한 처리 내용과
삭제 요청 방법은 서비스의 개인정보처리방침을 기준으로 한다. Neon DB에 저장된
생성 결과는 생성 시점부터 7일 동안 보관하며, 보관 기간이 지나면 일 1회 실행되는
자동 삭제 작업을 통해 파기한다.

## 9. 제품 원칙

### 간단해야 한다

사용자는 별도의 설명 없이 입력과 생성을 완료할 수 있어야 한다.

### 빨라야 한다

서비스 접속부터 결과 확인까지 오래 걸리지 않아야 하며, 생성 중이라는 사실을
명확하게 알려야 한다.

### 결과가 재미있어야 한다

입력 문장을 단순히 길게 바꾸는 것이 아니라 사용자가 웃고 공유하고 싶은 결과를
만들어야 한다.

### 모바일에서 편해야 한다

작은 화면에서도 입력, 스타일 선택, 결과 확인과 공유가 편리해야 한다.

### 사용자가 통제할 수 있어야 한다

사용자는 과장 스타일을 직접 선택하고 생성 전에는 이전 단계로 돌아가 입력을
수정할 수 있어야 한다.

### 실제 데이터 처리와 안내가 일치해야 한다

서비스 화면, 개인정보처리방침과 실제 코드의 저장 및 공유 방식이 서로
어긋나지 않아야 한다.

- 입력 길이와 형식 검증
- 의미 없는 활동 입력 방지

## 13. 성공 여부를 확인할 지표

향후 사용량 분석 기능을 도입할 경우 다음 행동을 확인한다.

- 방문자 중 입력을 시작한 비율
- 생성 요청을 완료한 비율
- 결과 이미지 저장 또는 공유 비율
- 사용자가 가장 많이 선택한 과장 스타일
- 생성 과정에서 이탈한 단계
- API 생성 실패와 요청 제한 발생 횟수

현재는 별도의 분석 도구를 연결하지 않았다.
